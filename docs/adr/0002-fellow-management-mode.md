# Fellow Management Mode

Each **Fellow** has a **Management Mode** that governs how their *weekly* schedule is produced: **Imported** (frozen exactly as supplied by an external workbook) or **Managed** (the solver assigns weeks; **Annual Rules** may pin specific weeks for vacation, exam, or conference). Nights and weekends are solver-assigned in both modes — management mode is strictly about the weekly layer.

This distinction was previously unnamed and re-derived independently in several places: the empty-week forbidding in `build_full_schedule_opb`, the `locked_fellow_indices` set used to skip per-fellow weekly rules, the `staffing_per_week` locked-fill softening, and the `dual_stroke_window` locked-stroke count. Each asked "is this fellow locked?" in its own way, so the answer could drift. They are now resolved in exactly one place — `ScheduleSolverConfig` (`imported_fellow_names`, `management_mode`, `imported_fellow_indices`, `imported_shift_counts`) — with `ManagementMode` as the explicit type.

Mode is set from **provenance**, not inferred from how much of a schedule happens to be filled: importing a workbook makes those fellows Imported (recorded in `locked_assignments`); everyone else is Managed. A Managed fellow with a few pinned weeks (a vacation request, the ISC conference week) is *not* Imported — their per-fellow **Constraints** stay fully enforced, and only the named weeks are fixed via `specific_assignment` **Annual Rules**. This is why pins must be expressed as `specific_assignment` rules under the current `specific_assignments` config key, never folded into `locked_assignments` (which would silently disable that fellow's other rules).

An Imported fellow's per-fellow weekly **Constraints** (`shift_total`, `max_consecutive`, block rotations, etc. — the `PER_FELLOW_KINDS` set) are skipped, because the external workbook already determines those weeks; enforcing them again could only conflict with the import. Group-wide and coverage **Constraints** still apply to everyone. When an Imported fellow already fills a per-week staffing cap, that week's cap is softened (the workbook exceeds it and we cannot also enforce it on the remaining fellows); this softening, too, now reads the single `imported_shift_counts` resolver.
